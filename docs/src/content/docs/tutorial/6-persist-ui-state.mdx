Application data and UI state can both live in LiveStore. The difference is
how you model their distribution: synced events are sent to the sync backend,
while client-only events stay on the current client.

In this chapter, the unfinished todo input and selected filter are scoped to
one browser session. They use an ordinary SQLite table, explicit client-only
events, and explicit materializers.

## Define the UI-state table

Add a normal table with a session id as its key:

```ts title="src/livestore/schema.ts"
import { Events, makeSchema, Schema, State } from '@livestore/livestore'

export const Filter = Schema.Literals(['All', 'Active', 'Completed'])
export type Filter = typeof Filter.Type

export const tables = {
  todos: State.SQLite.table({
    name: 'todos',
    columns: {
      id: State.SQLite.integer({ primaryKey: true }),
      text: State.SQLite.text({ default: '' }),
      completed: State.SQLite.boolean({ default: false }),
    },
  }),
  uiState: State.SQLite.table({
    name: 'uiState',
    columns: {
      id: State.SQLite.text({ primaryKey: true }),
      input: State.SQLite.text({ default: '' }),
      filter: State.SQLite.text({ schema: Filter, default: 'All' }),
    },
  }),
}
```

The row key makes ownership explicit. This tutorial uses `store.sessionId`, so
each browser session has its own draft and filter.

## Define client-only events

Name events after the UI actions they represent:

```ts title="src/livestore/schema.ts"
export const events = {
  // Keep the existing todo events from the previous chapter.
  todoCreated: Events.synced({
    name: 'v1.TodoCreated',
    schema: Schema.Struct({ id: Schema.Number, text: Schema.String }),
  }),
  todoDeleted: Events.synced({
    name: 'v1.TodoDeleted',
    schema: Schema.Struct({ id: Schema.Number }),
  }),
  todoCompleted: Events.synced({
    name: 'v1.TodoCompleted',
    schema: Schema.Struct({ id: Schema.Number }),
  }),
  todoUncompleted: Events.synced({
    name: 'v1.TodoUncompleted',
    schema: Schema.Struct({ id: Schema.Number }),
  }),
  todoDraftChanged: Events.clientOnly({
    name: 'v1.TodoDraftChanged',
    schema: Schema.Struct({ id: Schema.String, input: Schema.String }),
  }),
  todoFilterChanged: Events.clientOnly({
    name: 'v1.TodoFilterChanged',
    schema: Schema.Struct({ id: Schema.String, filter: Filter }),
  }),
}
```

Client-only events are persisted and observed by sessions of the same client,
but are not pushed to the sync backend.

## Materialize each event explicitly

The insert side of each upsert supplies a complete initial row. The conflict
side updates only the field represented by the event:

```ts title="src/livestore/schema.ts"
const materializers = State.SQLite.materializers(events, {
  'v1.TodoCreated': ({ id, text }) =>
    tables.todos.insert({ id, text, completed: false }),
  'v1.TodoDeleted': ({ id }) => tables.todos.delete().where({ id }),
  'v1.TodoCompleted': ({ id }) =>
    tables.todos.update({ completed: true }).where({ id }),
  'v1.TodoUncompleted': ({ id }) =>
    tables.todos.update({ completed: false }).where({ id }),
  'v1.TodoDraftChanged': ({ id, input }) =>
    tables.uiState
      .insert({ id, input, filter: 'All' })
      .onConflict('id', 'update', { input }),
  'v1.TodoFilterChanged': ({ id, filter }) =>
    tables.uiState
      .insert({ id, input: '', filter })
      .onConflict('id', 'update', { filter }),
})

const state = State.SQLite.makeState({ tables, materializers })
export const schema = makeSchema({ events, state })
```

## Read without writing

A new session has no UI-state row yet. Use a query fallback to return the
initial value without inserting anything:

```ts title="src/livestore/queries.ts"
import { queryDb } from '@livestore/livestore'
import { tables } from './schema.ts'

export const uiStateQuery = (id: string) =>
  queryDb(
    tables.uiState.where({ id }).first({
      behaviour: 'fallback',
      fallback: () => ({ id, input: '', filter: 'All' as const }),
    }),
    { label: `uiState:${id}`, deps: id },
  )
```

The first edit commits an event; its upsert creates the row. Reads remain
read-only and every write remains attributable to an application event.

## Connect the React component

Read the row with `useQuery` and pass the concrete session key in every event:

```tsx title="src/App.tsx"
import { queryDb } from '@livestore/livestore'
import { events, type Filter, tables } from './livestore/schema.ts'
import { uiStateQuery } from './livestore/queries.ts'
import { useAppStore } from './livestore/store.ts'

export const App = () => {
  const store = useAppStore()
  const { input, filter } = store.useQuery(uiStateQuery(store.sessionId))
  const todos = store.useQuery(
    queryDb(
      tables.todos.where({
        completed:
          filter === 'Completed' ? true : filter === 'Active' ? false : undefined,
      }),
      { deps: filter },
    ),
  )

  const updateInput = (nextInput: string) =>
      store.commit(
      events.todoDraftChanged({ id: store.sessionId, input: nextInput }),
      )

  const updateFilter = (nextFilter: Filter) =>
    store.commit(
      events.todoFilterChanged({ id: store.sessionId, filter: nextFilter }),
    )

  const addTodo = () => {
    if (input.trim() === '') return
    store.commit(
      events.todoCreated({ id: Date.now(), text: input }),
      events.todoDraftChanged({ id: store.sessionId, input: '' }),
    )
  }

  return (
    <main>
          <input
            value={input}
        onChange={(event) => updateInput(event.target.value)}
        onKeyDown={(event) => event.key === 'Enter' && addTodo()}
                />

      {(['All', 'Active', 'Completed'] as const).map((value) => (
        <button key={value} onClick={() => updateFilter(value)}>
          {value}
              </button>
          ))}

      <ul>
        {todos.map((todo) => <li key={todo.id}>{todo.text}</li>)}
      </ul>
    </main>
  )
}
```

Refresh the page after typing a draft or choosing a filter. The explicit
client-only event has persisted the row locally, so the same session resumes
with its previous UI state.

## Test the app

Run the development server, create a few todos, change the filter, and refresh
the page. Verify that synced todo events still follow the previous chapters'
behavior while the draft and filter remain local to this client.
